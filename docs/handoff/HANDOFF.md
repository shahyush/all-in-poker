# All In — build, test and host contract

## 1. Product and scope

Tanisha and Aayush are building a private poker PWA for friends. The host sends an invite; someone unfamiliar with the app should be able to enter a nickname, join with their chosen buy-in, take a seat, understand their turn and play an entire session without instruction. Their next visit should recover their own seat/history, not someone else's account. The app should feel like a considered private club or premium editorial retail experience, not a casino promotion or a dashboard full of controls.

Build a real, server-authoritative app. Scope includes multiple independent tables; 2–9 physical seats; Dealer's Choice every hand; Texas Hold'em and Omaha 4/5/6; blinds and per-player antes; cash UTG straddle; legal betting; side pots, ties, refunds and odd chips; once/twice runouts; optional reveal after an uncontested win; cash rebuys and accounts; single-table tournaments; chat; persistent player history; reconnect, host succession and automatic cleanup. Provide actual dealing and board animations.

This is play chips only. “Cash game” means a ring-game format, not money. Use “Session accounts,” not a financial wallet. No deposits, monetary withdrawals, payments, rake, marketplace, public matchmaking or real-money settlement feature. Tournaments are single-table; multiple separate tournaments may run. No balancing, late tournament registration, manual pause or manual close-table control.

Support iPhone Safari and Add to Home Screen first, plus Android Chrome/PWA. Portrait and landscape are two layouts of one game state. Do not require rotation or installation to play. Do not build separate desktop/tablet variants. Larger windows may contain the phone product without breaking it.

## 3. Entry, identity, privacy and recovery

Separate these concepts: group membership/admission, stable player identity, an authenticated device/session, table membership, and seat ownership. A group password does not prove the identity of an existing player. Display names can duplicate and change. Never merge two Sams or give either access to the other's cards.

Recommended implementation: use Supabase anonymous authentication as the transport session, with a stable application player record and server-verified group membership. Anonymous sessions still have distinct authenticated user IDs and need RLS; anonymous sign-in alone must confer no access to tables or profiles. Inspect whether anonymous sign-in is currently enabled and whether existing accounts need migration. Do not create fake email addresses. Do not discard existing valid account/history ownership. A current auth UID can remain the player key when viable; if supporting recovery across newly created auth sessions, use a carefully restricted player-to-auth binding rather than copying chips/history.

First visit: retain invite destination → enter nickname and group password → server validates password and creates/links the player's own membership → show table preview → intentional buy-in/join. Returning valid session skips entry. Without an invite, enter the private lobby. Group password must be hashed with a suitable password hash on the server, rate-limited and excluded from client bundles, logs and URLs. The production password is never `play` or another sample value. Configure through an authorised secret mechanism, not chat. Allow owner rotation/revocation without merging or resetting legitimate identities.

Provide optional “Save player code” in profile, outside the join path. Generate a strong random private recovery secret (at least 128 bits), store only a verifier and present it once with a copy/download option. Recovery must require that secret, rate-limit failures, atomically rebind the authenticated session, revoke/rotate the used secret and prevent session fixation. Group/password/nickname alone cannot recover someone. A new device can alternatively be linked from an already authenticated device using a single-use short-lived high-entropy link. Choose one complete recovery method, not two half-built flows. Do not promise automatic cross-device identity if the user did not save a code. Browser storage clearing can lose access. Provide a clear truthful explanation; never fabricate old history.

No email, phone, contacts, location, marketing analytics or advertising SDK. Keep nickname, simple avatar, game membership, ledger/history and security/session records needed for operation. A minimal privacy explanation says this; “we collect no data” is false. Do not log recovery secrets, session tokens, hidden cards, remaining deck or chat bodies. No third-party font fetch at runtime; self-host approved licensed assets or use system fallbacks.

A second device with the same identity sees the same membership/seat and competes through version checks. It never gets another buy-in. Restrict one actively seated table per player for V1; authorised lobby/history viewing can coexist. Independent players use separate sessions, never shared credentials.

## 5. Poker contract

### Deck, deal and evaluation

Use one standard 52-card deck, no jokers, no burns in this digital profile. Shuffle the full deck once per hand on the server using unbiased Fisher–Yates with cryptographic random integer sampling and rejection of modulo bias. Fail closed if secure randomness is unavailable. Commit the shuffled deck and frozen hand/rules privately before any reveal; draw sequentially. Never reshuffle the tail after bets, pick outcomes based on chip stacks, compensate for losses, favour a host/new player or seed with timestamps/hand numbers. No Math.random in the live dealer. Seed/deck injection belongs only in a separate test harness/build, unreachable by production HTTP/RPC commands. Preserve the existing backend's CSPRNG primitive if correct.

No need to add blockchain, external randomness service or a misleading “provably fair” badge. Ordinary statistical checks cannot prove lack of rigging; they supplement source review, injection tests and secure server authority. Administrative database access remains trusted infrastructure, not a player capability.

Freeze the dealt participants before the choice. Capacity for one board is N×H+5. A flop double runout is N×H+7; a turn double runout is N×H+6. O5 at nine players uses exactly 52 cards for a flop double runout; O6 at seven uses 49. Folded cards remain consumed. Never recycle them. With eight/nine participants O6 is disabled before selection. Validate on server even if UI disabled. Decline impossible variants without partial deals/credits.

First dealer button is securely random among eligible seats. Deal one card per seat clockwise starting left of the button, repeat 2/4/5/6 times. Use physical seat indices. Cards may be represented as integer IDs internally and mapped for display, but conversion must be tested. Hold'em takes best five of seven (0–2 hole cards); Omaha takes exactly two of 4/5/6 hole cards and exactly three of five board cards. Ace-low straight is five-high; no wrap straights; suits never break ties. Validate unique and known card IDs before evaluating. Evaluate every pot/board separately.

### Blinds, antes, button and action

SB and BB positive integers with SB < BB. Ante is per dealt player, zero/off by default, paid before blinds; short stack pays what remains. Keep nominal bring-in separately from actual chips. HU: button is SB, acts first preflop and last after flop. At 3→2 transition do not give the surviving old BB the BB again. Cash moving button and tournament dead button need real physical-seat rules, not the candidate's compact-array approximation. If tournament nominal button is empty, next live clockwise player chooses the game; preserve correct blinds and action order. Missed blinds must survive sit-out, reconnection and reseating.

Straddle is cash only, optional at creation, only original UTG, only when ≥3 dealt players, full 2×BB available after ante. Do not move UTG to another seat when UTG is all-in from ante. No button/double/re-straddle. It is live, first preflop action moves to its left, straddler retains final option. Initial full raise increment is 2×BB, making minimum raise-to 4×BB; postflop resets to BB. No response by cutoff skips. Do not debit twice on retry.

Actions use integer chip units with explicit safe ranges. Recommended initial technical limit: each credit and each resulting table liability ≤10^12 chips, with checked sums and database BIGINT; client numbers must remain exactly representable. This is overflow protection, not a 20-unit rebuy cap. Accept canonical positive digit strings for amount fields; reject `1.5`, `-2`, `1e2`, Infinity, unsafe values and embedded junk. Never strip characters so 1.5 becomes 15 or -2 becomes 2. Clearly show formatted amounts without changing their value.

Command uses `raiseTo`, the total current-street contribution, not “raise by.” Show additional payment separately. Server returns legal actions, call/owed, min/max raise-to and any reason raising is closed. Minimum opening bet BB; subsequent full raise increment at least previous full raise. Short all-in allowed when stack cannot make a full raise; it does not automatically reopen action. Track each player's last faced amount and cumulative short raises. A prior check followed by a sub-BB opening all-in alone does not reopen that checker's raising rights under the adopted TDA rule. An unacted player retains options. Never show All-in in PLO when it exceeds the pot cap. Never offer a raise no opponent can contest.

For ordinary full-blind PL: P = total actual committed chips before action including current wagers; C = full call owed; S = actor's current street contribution. Max additional = P+2C; max raise-to = S+P+2C, capped by S+stack. Preflop short/dead blinds use the nominal full-blind convention in cap calculation only. Example SB5/BB10 with BB posting only3: unopened UTG PL cap is35, not28. Actual chips remain8 before action; never inflate the ledger. Test straddle and ante caps separately. Preserve nominal BB bring-in after short BB. Short calls use the player's available stack.

A street closes only when all non-folded players with chips have fulfilled their obligations and completed required action. Do not skip the BB/straddler option. Postflop action begins left of button. After the river settle; if everyone but one folds, award immediately without exposing unnecessary board cards. Remove unmatched excess before building pots.

### Pots and chip conservation

Build side pots from sorted contribution thresholds. Include folded contributions in amounts; exclude folded players from eligibility. Leave/disconnect/removal never erases an all-in player's eligibility. Split each pot separately. For two boards, Board A receives an extra chip when the pot is odd. Split each board share among tied winners; distribute odd remainder clockwise left of button among those tied winners. No rake, no rounding loss, no suit-based tiebreaker. Record refunds separately from winnings. Return authoritative per-pot breakdown and winning five cards where public.

During a hand sum(remaining stacks + hand contributions) is constant, excluding only separately recorded boundary credits/exits. At session level sum(added) = sum(available stacks + committed chips + chips taken off). Settled sum of cash nets is zero. Assert these invariants transactionally and in tests. Stop further progression on an invariant violation, preserve protected diagnostic evidence and surface a brief table error; never silently manufacture a balancing credit.

### Run once/twice

Normal-betting proposal: cash only, flop/turn, player's turn, before any wager on that street (earlier checks allowed), no outstanding call, no pending command, one proposal per street globally. “Run once” and “Run twice” both mean stop all further betting if unanimously agreed. One vote includes every nonfolded live claimant, including all-ins with only main-pot claims. Freeze electorate and remaining actor time atomically. Proposer consents. Others agree or keep playing; votes private until aggregate outcome. Leaving does not reduce the electorate. An explicit decline ends immediately; silence at eight seconds declines. Restore identical actor/street and exact remaining time, not a fresh clock or minimum five seconds. A bet/proposal race accepts one authoritative transition.

Unanimity closes betting irrevocably for every pot and future street. Run once must not reopen river betting. Run twice shares already exposed flop/turn; future cards in each tail are distinct and drawn from the same private deck. Split pots by the rule above. Reset all runout state next hand. A failed proposal is not offered automatically again on that street.

If no betting remains possible, use a five-second inline once/twice offer after flop/turn. Any decline/silence means once. Preflop all-ins first receive one shared flop, then the same tail offer; no preflop proposal UI that throws “flop/turn only.” If already at river settle directly. Tournaments run once. No full preflop double-board option. Server validates deck capacity before committing a vote outcome.

### Showdown and optional reveal

At a contested showdown reveal all nonfolded contestants' complete hands, including losing hands, under this explicit simple house rule. No private folded cards. After an uncontested award only the winner receives an optional three-second show/muck window. Each card independently revealable; Show all reveals all; Muck closes further reveal, leaving previously shown cards public. No response leaves all unshown cards hidden. Server validates owner, hand ID, result type, card index and deadline. Reveals are irreversible, idempotent and retained in public hand history. Never send the full private hand in a public event and then rely on CSS hiding.

## 6. Session accounts, reloads, tournament and cleanup

Cash ledger is append-only, with unique source IDs for initial buy-in, approved reload credit, hand settlement and exit. A reload request can be made during a hand but credits only at the next safe boundary after host approval. Positive multiples of table's original buy-in unit remain allowed regardless of past reloads. Initial chosen buy-in may be multiple units. No zero-stack-only restriction. Log requested/approved/rejected/cancelled/credited with actor/time. Host self-reloads are explicitly self-approved and visible in accounts; no hidden chip grant. Host role/epoch must still be current when deciding another player's request. A cancelled/pending-leaving request cannot later credit. Replay of the same settlement snapshot cannot overwrite an already credited reload.

In a live hand, show available stack and committed chips distinctly. Accounts net = available + committed + taken off − added; after settlement committed=0. In final summary current stack=0 after cash-out and taken off records the exit amount. Historical totals must not disappear when a member leaves/rejoins. Reentry creates a new membership/ledger event attached to the same player/session; never overwrite the previous exit. Enforce one active seat, not one historical membership.

Tournament uses its own ledger of issued starting chips and standings, not cash profit/loss. Equal stacks, registration locks atomically at start, no late joins. Rebuys Off in V1; any optional enabled mode requires a separately specified policy before exposure. Levels use server elapsed wall time from tournament start and cumulative row durations. If several boundaries elapsed during one hand, next hand takes the correct current scheduled level, not only one increment. Do not alter active hand's blinds/ante mid-hand. After last row hold final level without invented rows or overflow. Display active hand blinds and next-hand change clearly.

Eliminate only after all side pots/refunds settle. For simultaneous busts, larger hand-start stack places higher; equal start stacks share a place, using competition ranking (two tied second makes the next fourth). Record hand-start stacks and elimination event. One player remaining wins. Tournament leave/removal/disconnect does not withdraw or destroy chips; the abandoned stack continues legal forced bets/check-fold until eliminated. Removed member loses live access; own archived summary remains available. If everyone absent for 30 minutes, settle in-flight hand, archive as abandoned with partial standings and no fabricated champion.

Cash timeout checks if legal, otherwise folds, and counts as a missed action either way. After two consecutive missed opportunities, sit out at next boundary; a genuine accepted manual action resets the consecutive count. Preserve chips and missed-blind obligations. Temporary disconnect alone is not leave. Returning uses the same player/seat and deadlines. All-in actors remain live in relevant pots even after departure/removal.

Host succession: after 30 seconds without valid host presence, choose connected eligible member by earliest membership join time, then physical seat, then player ID. Transfer once with a new host epoch. Old host reconnecting does not seize it back. If no successor, server play/timers continue; approvals wait. Presence is advisory, deadlines are durable. Use server heartbeat receipt time; do not trust client timestamps. Expired/revoked sessions cannot keep an abandoned table alive.

When nobody is connected, finish the in-flight hand via server deadlines but hold new hand creation until a member returns or abandonment resolves. Tournament wall time still advances. This automatic waiting state is not a manual pause control; it avoids manufacturing an unattended champion.

Normal cleanup when everyone actually left: no unresolved hand/pot/credit, durable summaries and member access grants committed, then delete live state/cards/presence/chat. Keep a tombstone and deduplication horizon so late commands cannot recreate a table or grant credits. Empty waiting tables may archive immediately after last departure. All-absent abandoned cash tables finish the current hand via legal timeouts, settle all exits, archive and clean. Do not deal indefinite unattended hands when fewer than two eligible cash players remain. Retain public hand/session summaries scoped to past participants. Proposed privacy default: delete private deck/hole storage after settlement and authorised reveals are recorded; private failed-invariant diagnostic retention at most seven days, access restricted and never public. Do not retain opponents' mucked cards in history. Delete ordinary chat at session archive; document that in privacy copy. Revisit hosting-provider security log retention explicitly rather than promising zero logs.
